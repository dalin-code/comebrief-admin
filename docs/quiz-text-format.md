# 测验文本格式（粘贴导入 + AI 整理）

> 入口：`/admin/quizzes/create` → 右上角 **BATCH IMPORT** → 顶部切到 **文本**。
> 代码：`lib/quizText.ts`（解析 + 四层闸）、`lib/quizTextPrompt.ts`（AI 整理的提示词）、
> `app/api/admin/quiz/text/route.ts`（整理接口）、`scripts/check-quiz-text.mts`（断言）。

## 为什么要有这条路

JSON 那条路（`docs/quiz-json-format.md`）能跑，但它的形状是**给机器看的**：一个对象、四个结果、
八道题、每个选项一个 `primary`。人写稿子的时候手上不是这个形状 —— 手上是
「标题一行、结果四段、每题四个选项」这种段落。硬把段落塞进 JSON，踩的永远是引号、
尾逗号、三个反引号，而不是内容本身。

所以这里换一个**人本来就写得出**的格式：行首标签 + 段落标题。代价是解析器要自己写，
好处是**粘错的提示能指到行号**，而不是一句 `Invalid JSON Format`。

两条路的产物是同一个东西：一份 `QuizKit` → `compileQuizKit` → 草稿行。
文本这条路只是多了一层「段落 → 字段」，后面的校验、编译、落库全复用，没有第二套规则。

## 模板

点框头上的 **模板** 会插入下面这份（`QUIZ_TEXT_TEMPLATE`，它自己必须过全部四道闸 ——
`npm run check:text` 盯着这一条，模板坏了 CI 先红）。

```
TITLE: What Kind of 2AM Person Are You?
HOOK: Eight taps, one verdict. We tell you who you are when the city is asleep.
TOPIC: pop-culture
TAGS: Internet Lore
AXIS X: Solo ←→ Crowd
AXIS Y: Calm ←→ Restless

== RESULT 1 | TL | pose=wave ==
NAME: The Quiet Watcher
SHORT: Watcher
...
== Q1 | Monday, 2:07 AM ==
Your phone lights up. The group chat is on fire. You…
A. Read all of it, type nothing.          (i1)
B. Send one perfect meme, then go quiet.  (i2) (b)
C. Screenshot it for the archive.         (i1)
D. Reply to all four people at once.      (i3)
```

完整模板以 `lib/quizText.ts` 里的 `QUIZ_TEXT_TEMPLATE` 为准（点「模板」看到的就是它）。
下面只讲**规则**，因为规则才是会挡住你的东西。

## 字段

### 篇头（一篇一份）

| 行 | 必填 | 说明 |
|---|---|---|
| `TITLE: …` | ✅ | 一篇的第一行。**重复出现 `TITLE:` 会被当成新的一篇** |
| `HOOK: …` | 建议 | 副标题，≤ 140 字（超了只 warning） |
| `TOPIC: …` | 建议 | 旧分类词汇，如 `pop-culture` / `internet-life` / `work-study` |
| `TAGS: … / …` | 建议 | 1–3 个标签，`/` 分隔 |
| `AXIS X: 低端 ←→ 高端` | ✅ | 结果页地图的横轴。两端都要写字 |
| `AXIS Y: 低端 ←→ 高端` | ✅ | 纵轴同上 |

### 结果段（恰好 4 段）

段头必须写成 `== RESULT n | 象限 | pose=名字 ==`：

- `n` = 1–4，**这个序号就是选项的映射目标**（见下）；
- 象限只能是 `TL` / `TR` / `BL` / `BR`，**四个结果必须各占一个角**，撞车是 blocker
  （不撞车才说明这四段文案真的在问两件不同的事）；
- `pose` 只能是 `shades` / `wave` / `love` / `worry`（`AXE_POSES`）。写了别的值是 blocker
  （`pose="cool"` 不认识），但**两个结果用同一个 pose 只是 warning** —— 角色由象限决定，
  pose 只决定「这只朋友摆什么表情」（见 `docs/quiz-folk-poses.md`）。

段内字段：

| 字段 | 必填 | 长度 | 用途 |
|---|---|---|---|
| `NAME:` | ✅ | 2–4 词 | 结果名，海报标题 |
| `SHORT:` | ✅ | ≤ 2 词 | 地图上的标签；也是 `→ Short` 的目标 |
| `HEADLINE:` | ✅ | ≤ 90 | 结果页第一句 |
| `QUOTE:` | ✅ | ≤ 140 | 引语（不用自己加引号） |
| `READ:` | ✅ | ≤ 320 | 3–4 句正文 |
| `STATS: a / b / c` | ✅ | 3 条 | 结果页的仪表 |
| `PILLS: a / b` | ✅ | 2 个 | 标签胶囊 |

**这些为什么全是必填**：缺任何一项，前台 `ResultView` 会**静默**降级回旧版式 ——
页面照样能打开，只是「不是最新那套」，没人会自己发现。这里把它变成粘贴时就能看见的
blocker。

### 题目段（6–10 段）

段头 `== Q1 | Monday, 2:07 AM ==`，`|` 后面是可选的场景时间戳（≤ 40 字，可以整段省略，
写成 `== Q1 ==` 也行）。

题目行就是段头下面那一行正文（≤ 120 字）。每题**恰好 4 个选项**，每行以 `A.` `B.` `C.` `D.` 开头：

```
A. <选项文字，≤ 90 字>  (i1)
B. <选项文字>           (i3) (b)
```

- `(i1)` / `(i2)` / `(i3)` = 能量档：1 是「几乎没反应」，3 是「整个人扑上去」。
  它会进结果页的配比与雷达，**不是装饰**；缺了是 blocker。
- `(b)` = 这题里**最不像多数人会选**的那个选项（bold 项）。每题恰好一个，必须换着位置放。
- 这两个标记的顺序随便写：`(i3) (b)` 和 `(b) (i3)` 一样能读。

## 选项按**位置**映射（最重要的那条规则）

`A` 指向结果 1、`B` 指向结果 2、`C` 指向结果 3、`D` 指向结果 4 —— 不是按文案猜，也不是按选项里的关键词。

这条规则不是为了省字段，而是为了让**四个选项天然是「同一个瞬间的四种活法」**。
一旦允许「A 和 C 都指向结果 2」，人写起来就会退化成四句互不相干的话，
而结果页的配比表会指向同一批选项 —— 引擎不报错，体验塌了。

两处逃生口：

| 写法 | 效果 |
|---|---|
| `C. Mute the chat. (i2) → Menace` | 这个选项改成指向 `SHORT`（或 `NAME`）为 `Menace` 的那个结果 |
| `C. Mute the chat. → menace` | 同上；大小写、空格、标点都做了归一化（`normalizeArchetypeId`） |

`→` 也可以写成 `->`、`=>`、`»`。**找不到对应结果**时不会悄悄改数据：按顺序映射，
并在这一行挂一条 warning（`→ xxx 找不到对应结果`）。

⚠️ 用箭头改完以后，同一题里如果出现**两个选项指向同一个结果**，`mapping` 规则会红 ——
这是故意的：那是「配平」问题，得换文案，不是改映射能绕过去的。

## 题量 6–10

AI 起草那条路固定 8 题（`KIT_QUESTIONS`），但**人手上的稿子不总是 8 题**。
这条路径把题数规则放宽到 6–10：

- < 6 → blocker（题目太少，四个结果分不开，枚举里会出现永远抽不到的原型）；
- 6 ≤ n ≤ 10 → 能存，但挂一条 warning 说明「不是模板的 8 题」（不是错误，只是提醒）；
- > 10 → blocker（手机上答不完，且枚举成本开始影响编辑器的手感）。

## 四层闸

文本进库要过四道闸，**外层永远先报**（内层的前提是外层已经过了）：

| # | 闸 | 查什么 | 在哪 |
|---|---|---|---|
| 1 | 语法 | 篇头 / 段头 / 选项行能不能读出来；行号对不对 | `lib/quizText.ts` 的 `parse*` |
| 2 | 契约 | `validateQuizKit` 的 5 条规则（题数 / 结果数 / 选项数 / 映射 / 名字），题数放宽到 6–10 | `lib/quizKit.ts` |
| 3 | v3 版式 | 象限、pose、两条轴、每个选项的 intensity、每题一个 bold | `v3Issues` |
| 4 | 引擎体检 | 全枚举 65,536 种组合：**死区**（有原型永远抽不到）、结果名重复，以及健康分 / 平局率 / 命中率 | `lib/quizAxes.ts` 的 `auditAxeQuiz` |

**第 4 层是关键**：`reachable`（某个结果永远抽不到）是一类**静默**故障 ——
页面照常渲染，只是永远给出同几个结果，人评审时看不出来。第 4 层把编译后的全枚举跑一遍，
有死区就直接红，不许导入。

体检里的**非结构性**结果（健康分、平局率、每个原型的命中率）显示在预览的芯片上，
不作为 blocker —— 那些是文案质量问题，该在编辑器里改，不该堵在粘贴这一步。


### 错误码

`QuizTextIssue.code` 是机器可读的判据（`scripts/check-quiz-text.mts` 按它断言），
界面上每一行的「第 N 行」都可以点回文本框：

| code | 典型文案 |
|---|---|
| `syntax` | 第 12 行读不出字段，已忽略 |
| `title` | 缺 TITLE:（每篇的第一行必须是标题） |
| `archetypes` | 一段结果都没读到 —— RESULT 段头没被认出来 / 读到 3 个结果，要 4 个 |
| `questions` | 一道题都没读到 —— Q 段头没被认出来 / 题量 5 不在 6–10 之间 |
| `options` | 第 3 题只有 3 个选项 |
| `names` | 第 2 题有两个选项指向同一个结果 / `→ xxx 找不到对应结果` |
| `quadrant` | 缺象限 / 两个结果都在 TL |
| `pose` | 没有 pose / `pose="cool"` 不认识（blocker）· 两个结果都用了 pose=wave（warning） |
| `axis` | 缺两条轴名（AXIS X / AXIS Y） |
| `intensity` | 第 12 行的选项没有 (i1)–(i3) |
| `bold` | 第 3 题没有 (b)（或有两个） |
| `language` | TITLE 写的是中文 |
| `length` | TITLE 有 132 字（建议 ≤ 120） |
| `topic` | 分类认不出来，已回落到 … |
| `audit` | 结果名重复：1 组 / X 永远抽不到 |

`level` 只有两档：`blocker`（红了不能存）和 `warning`（能存，但该看一眼）。
框头的徽章只看 blocker —— 所以「绿了」就是一定能导入。

## 一个框 = 一篇，`---` 可以拆

- 一个框里的文本就是一篇。**出现第二个 `TITLE:` 会自动切成两篇**（一次粘贴多篇时不会互相污染）。
- `---`（三个以上 `-`）/ `===` / `***` 单独一行也是分隔符。
- 底部 **整段粘贴拆分** 可以把一整段一次拆成多个框 —— 拆完每个框各自校验。

### 关掉弹窗不会丢稿

每次改动 600ms 后会把**文本**（多框 + 输入方式 + 拆分区）写进 `localStorage`
（键 `quiz-batch-import-draft:v1`，24 小时过期），重开弹窗时自动接回来，
顶部挂一条「已恢复上次没导入的稿子（时间）—— 清空重来 / 知道了」。

为什么值得单独占一节：「AI 整理」一次要等十几秒，而这段时间里最贵的东西就是那段稿子。
以前关掉弹窗、刷一下页面，它就从世界上消失了，而草稿箱里还是空的。
恢复**只发生在空的弹窗上**（不覆盖正在写的字），导入成功后这份草稿立刻删掉。

## AI 整理（✨）

框头的 **✨ AI 整理** 把当前文本发给 `POST /api/admin/quiz/text`，模型按同一份模板重写一遍，
**返回的还是文本**。但这一版**不会自动覆盖框里的稿子** —— 它会先变成一条「待采用」：

```
AI 整理好了这一版：结果 2 → 4 · 题 0 → 8 · 要修 2 → 0。还没写进框里 —— 先看，再决定。
[左右对照] [采用这一版] [放弃]
```

「左右对照」把当前稿子和 AI 版本并排铺开（两边都能滚），确认了才写入，写入后仍然可以撤销。
为什么要这一层：以前的实现是「拿到就回写」，于是模型输出被截断（或只整理了一半）时，
作者按下按钮的那一刻八道题就只剩四道 —— 而撤销栈里只有一份全量快照，再点一次原文就真没了。

**失败绝不碰原稿。** 接口失败一律 `ok: false` + `code`，且**不带 `text`**：

| code | 含义 | 框里会看到 |
|---|---|---|
| `TRUNCATED` | 模型写到一半撞上 `maxOutputTokens`（真凶是思考 token 吃额度，见下） | 「模型这次没写完就断了」+ 再试一次 |
| `PARSE_FAILED` | 回来了，但一段都认不出（没按模板写） | 「没按模板写」+ 再试一次 |
| `PROVIDER` | 供应商层失败（429 / 余额 / 超时），原样转发 `ai.error` | 供应商的原话 |
| `EMPTY` / `TOO_LONG` / `TIMEOUT` / `FATAL` | 入口与兜底 | 对应的那句话 |

成功时还会带 `summary: { before, after }`（`summarizeQuizText` 算的同一份数字）和
`partial`（输入 2 篇、输出只剩 1 篇时为 true，对比条上会额外标一句）。

⚠️ **`thinkingBudget: 0` 不能删。** Gemini 3.x 的思考 token 与答案共用 `maxOutputTokens`：
不传这个参数，它会先花掉大半额度「盘算怎么改」，剩下的只够写完前两篇，
`finishReason` 变成 `MAX_TOKENS`。同一个坑在 `app/api/ai/excerpt/route.ts` 踩过一次。

为什么回写文本、不回写对象：

1. **人得看得见模型改了什么**。回写成同一套模板，作者逐行对照，不满意一键放弃；
   如果是「点一下按钮，库里多了一卷我没读过的卷」，那就成了不可审计的自动化。
2. **接口自己也要过闸**。服务端拿到模型输出会再跑一次 `inspectQuizText`：
   解析不出任何一篇就直接 502（宁可报错，也不能把好东西换成一段没人能读的文字）。
3. **它不保证零 blocker**。模型可能只翻了一半、或者把象限写重了 ——
   这种情况仍然把文本交回去（连同 `issues` 和对比数字），让作者看着
   「结果 2 → 4」自己决定是采用还是放弃。比在服务端替人丢掉这次调用要好。

它做的事：补缺失字段、把中文翻成英文、补每个选项的 energy 档、补齐象限 / pose / 轴名。
它**不**做的事：换选题、重排四个结果、发明新题（那是 `lib/quizAi.ts` 的三段生成，
有趋势、热词和配平数学）。整理是**收敛**型任务：`temperature 0.3`、不重试。

提示词里的格式说明（`lib/quizTextPrompt.ts`）必须和解析器逐字对齐 ——
改解析器（比如新增一个字段）就要同步改那里，否则模型会稳定地写出解析器读不了的东西。

## 落库

和 JSON 那条路走**同一个** `buildDraftRow`：

- 只写 `status = 'draft'`、`active = false`，**绝不**顺手上线；
- `raw_data` 里带 `model: 'axes'`、`scoring_mode: 'axes'`、`archetypes`、`questions`、`axes`、`cover_url`；
- 不写 `results` / `questions_count` / `published_at`（这些由编辑器保存时再算）。

导入完去 `/admin/quizzes` 打开这篇，改封面、设时间，按「草稿 / 发布 / 定时」走原来的流程
（见 `docs/scheduled-publishing.md`）。

## 排查

| 现象 | 原因 |
|---|---|
| 框红了，报「一段结果都没读到 —— RESULT 段头没被认出来」 | 段头写成了 `RESULT 1` 还能读，`## RESULT 1` / `**RESULT 1**` 就不行了 —— 必须是 `== RESULT 1 \| TL \| pose=wave ==` |
| 框红了，报「一道题都没读到 —— Q 段头没被认出来」 | 段头不是 `== Q1 \| 场景 ==`（序号、`==`、竖线三样缺一不可） |
| 明明写了 4 个结果，报「读到 3 个」 | 有个段头少了 `==`，或者被 `---` 提前切成两篇 |
| 报「pose="cool" 不认识」 | `pose` 只有四个值；不是「你漏写了」，是「写了但不在这份名单里」 |
| 每题都报「缺 (b)」 | `(b)` 只写了一次，或者写在题目行上（要写在选项行尾） |
| 报「写的是中文」但正文是英文 | 中文在 `NAME:` / `PILLS:` 里，或者标题里有全角标点 |
| 报「X 永远抽不到」 | 每题的能量档全一样（都是 `(i1)`）—— 区分度被压平，引擎分不开四个结果 |
| 保存按钮灰着，但框是绿的 | 绿徽章只代表「这一篇能存」；按钮还看「是不是所有框都绿」+「有没有正在导入」 |

## 怎么验证

```bash
npm run check:text     # 模板自检 / 四层闸 / 行号 / 往返 / 拆分 / 6–10 题 / 四类负样本
npm run typecheck
```

`check:text` 也在 CI 里跑（`.github/workflows/checks.yml`）。它断言的第一件事是
**模板自己必须零 blocker 零 warning** —— 因为那个模板是被「插入」的，不是被「改」的，
坏了没人会发现。
